# Ванильные ворота B42 — разбор

Декомпилированные классы: `research/decompiled/` (IsoThumpable, IsoDoor, IsoObjectAnimations, SpriteModel*). Остальное — `E:\git\PZMining\decompiled`.

## Как рисуются ворота
- Тайл (спрайт) ↔ 3D-модель связываются в `media/spriteModels.txt`: `modelScript`, `translate`, `rotate`, `scale`, `animation` (`Open`/`Close`), `animationTime`.
- Для ворот (`fixtures_doors_fences_01`) закрытый и открытый тайлы разные: `_0/_1` — `animation = Open`, `_2/_3` — `animation = Close` (W и N).
- `modelScript` — `scripts/generated/models_isoobject.txt`: `mesh`, `texture`, `animationsMesh`, `shader = door`, `static = false`.
- Модели: `models_X/IsoObject/*.glb` (+ `.blend` в `blender/`). В glb лежат анимации `Open` и `Close` (0.5 с), каналы translation/rotation/scale на костях `DoorBone` и `PostBone`.

## Как открываются
`IsoThumpable.ToggleDoorActual`:
1. проверки (баррикада, замок, `isObstructed()` → «Blocked»),
2. `open = !open`, спрайт меняется на `openSprite`/`closedSprite`,
3. `square.RecalcAllWithNeighbours`, `sync(open?1:0)`, `PolygonalMap2.squareChanged`,
4. `PlayAnimation()` → `IsoObjectAnimations.addObject(obj, spriteModel, "Open"|"Close")` — анимация проигрывается один раз клиентом (на сервере не выполняется).
После анимации отрисовывается спрайт нового состояния (со своей `animation`/позой).

## Коллизия
- `getSpriteEdge(ignoreOpen)`: закрытая дверь — ребро N/W; открытая — другое ребро (N→W, W→N) либо E/S по флагам `attachedE/attachedS` тайла. Коллизия двери — логика ребра в Java, не флаги спрайта.
- Есть механизм «двойной двери»: свойство тайла `DOUBLE_DOOR`, `IsoDoor.toggleDoubleDoor`, `isDoubleDoorObstructed` — несколько клеток переключаются вместе.

## Вывод про offsetX/Y (результат прототипа)
- `IsoObject.getSpriteModel() != null` → объект рисуется через `IsoObjectModelDrawer.renderMain(...)`; `offsetX/offsetY` в этом пути **не используются**. Поэтому `setOffsetX/Y` на ванильной калитке ничего не делает (лог прототипа: slide стартовал без ошибок, на экране без изменений).
- Работающий путь для анимации — анимации внутри glb (кость `DoorBone`, translation), запускаемые через `IsoObjectAnimations`/спрайт-модель.

## Результат прототипа с моделью из Blender (SG_ChainLink)
- Свой `.glb` + `modelScript` + `spriteModel` из скриптов мода работают: модель рисуется, `Open`/`Close` анимируются, 2-клеточный лист не обрезается за пределами своей клетки. Носитель — любой тайл, модель подменяется `setSpriteModelName`; статичные детали — `IsoObject` с тем же приёмом.
- **Ось X зеркальна:** модельный +X (Blender X) в игре идёт в мир −x (для N-ребра). Вдоль оси ворот сборку раскладываем в −x; `Right` (положительный ход) открывается в −x. 
- В экспортах Blender нет объектных трансформаций (только локальная геометрия): положение объекта (`location`) надо задавать смещением `spriteModel`.
- **Ось Z тоже зеркальна** (модель в игре повёрнута на 180° вокруг вертикали: X и Z меняют знак). Для статичных деталей со смещением по Z относительно листа знак `translate_z` противоположен Blender: привод с Blender `y = −0.22` (внутренняя сторона листа) в игре ставится как `translate_z = −0.5 − 0.22`. Проверка по скриншоту: шток привода должен быть направлен на рейку листа, а ящик не должен закрывать сетку.
- **Итоговая формула размещения статичных деталей** (проверена в игре на приводе): модель в игре повёрнута на 180° вокруг вертикали (X и Z меняют знак), а `translate` из `spriteModel` применяется после поворота, в мировых осях. Для детали с Blender-положением `(b, y_b)` на клетке-носителе, сдвинутой на `k` клеток в −x от клетки листа: `translate_x = −0.5 − b + k`, `translate_z = −0.5 + y_b`. Для листа (`b = 0, y_b = 0, k = 0`): `(−0.5, −0.5)`. Приёмный столб `b=−0.04`: `−0.46`; роликовый `b=2.04, k=2`: `−0.54`; привод `b=2.18, y_b=−0.22, k=2`: `(−0.68, −0.72)`; рельса `b=k`: `−0.5`.

## Коллизия сборки (эксперимент, SG_Gate.lua; проверено в игре пешком)
- Видимый лист занимает клетки x0-1 и x0-2 (x0 — клетка приёмного столба). Двери-коллайдеры: лист на x0-1, вторая дверь на x0-2; блокеры открытого состояния (закрытые скрытые двери) на x0-3, x0-4. Лист-носитель сдвинут на клетку, модель компенсируется `translate_x = +0.5` (`*_G_*` spriteModel).
- Закрыто: `isBlockedTo` по N-ребру true на x0-1, x0-2. Открыто: свободны x0-1, x0-2, заблокированы x0-3, x0-4. Блокеры создаются при открытии и удаляются при закрытии, вторая дверь открывается и закрывается вместе с листом через `ToggleDoor` (обе `obstructed=false`).
- Открытые двери блокируют перпендикулярное W-ребро своих клеток (`openW=true`), это край проёма у столбов; проход по линии ворот пока не проверен отдельно.
- Хвост листа (~0.34 клетки за проём в сторону -x) выступает за последнюю клетку без коллизии. Ожидаемо: рядом с воротами должен идти забор/стена (карман), хвост перекрывает её. Опционально можно добавить блокировку клетки хвоста.

## Физика машин (IsoChunk.calcPhysics, Bullet) и препятствия
- Машина — динамическое тело Bullet, но мир для неё статичный и **по клеткам**: `IsoChunk.calcPhysics` собирает на клетку до 4 форм из набора `Solid`, `WallN/W/S/E`, `Tree`, `Floor`, лестницы, `FIRST_MESH+i` (пользовательские меши) и отправляет их через `Bullet.updateChunk`. Формы выбираются по свойствам спрайтов клетки: `solid/solidtrans/blocksight` или `IsoThumpable.isBlockAllTheSquare` → `Solid`; `collideN/W`, `windowN/W` → `WallN/W`; закрытая дверь в раме (`DoorWallN` + `doorN`, `!open`) → `WallN`; свойство спрайта `PhysicsShape` (Solid/WallN/W/S/E/Tree/Floor); свойство `PhysicsMesh = Base.<имя скрипта physicsShape>` → пользовательский меш (так сделаны рампы).
- У ванильных двустворчатых ворот `PhysicsShape` задан на закрытых тайлах (`WallN`/`WallW`) и на открытых (`WallS`/`WallE`), поэтому машина врезается в закрытые и задевает открытые. У наших спрайтов-носителей двери (`fixtures_doors_fences_01_129/131`) его нет, для машин ворота не существовали.
- Решение в моде (проверено в игре): скрытые статичные объекты-коллайдеры со спрайтом `fixtures_doors_fences_01_36` (`PhysicsShape = WallN`, модель `SG_Hidden`) на клетках, где ворота блокируют ходьбу (клетки проёма в закрытом состоянии, клетки кармана без забора), добавляются и убираются вместе с логической блокировкой (роль `collider`). Машина врезается в закрытые ворота.
- Идея плавной коллизии для машин (не реализована): скрипты `physicsShape` (меши в `media/models_X/...`, трансформ translate/rotate/scale) + свойство `PhysicsMesh` на спрайтах-носителях, которое можно задавать из Lua (`sprite:getProperties():set(...)`, ванильный Lua так делает). Менять носитель по ходу движения листа (доля клетки: 1/4, 1/2, 3/4). Нужны меши из Blender, отдельные спрайты-носители на градацию, проверка пересчёта физики чанка. Отложено: выигрыш в основном для 4-клеточных ворот.
- Препятствия: `IsoDoor.isDoorObstructed(door)` проверяет только транспорт (`vehicle.isIntersectingSquareWithShadow`) и `solid/tree` на клетке двери, не людей. Ванильная дверь при этом отказывает с надписью над персонажем `IGUI_PlayerText_DoorBlocked` («Дверь заблокирована», `setHaloNote`). У ворот: `SGGate.isBlocked(id, opening)` — при закрытии проверяются клетки проёма (+ `leaf:isObstructed()`), при открытии клетки кармана (`IsoGridSquare.isVehicleIntersecting`).
- Удары: `ISDestroyStuffAction` (кувалда) удаляет объект напрямую, без события `OnDestroyIsoThumpable` — события приходят только от ударов оружием и зомби; ворота при этом разрушаются целиком (`SGGate.destroyGate`).
